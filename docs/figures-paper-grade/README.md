# 复杂科研配图 SOP V1.2

适用：AI 方法总览、工业智能体机制、候选筛选与反馈更新。更新：2026-10-17。维护原则：每次交付记录新增问题、修复办法和已验证能力，不把未实测的软件标成可用。

这是一套制图流程。图是否适合投稿，还取决于真实方法、证据、目标会议格式和全文叙事；不能靠信息密度替代研究深度。当前两张图是独立绘制的概念样板，波形、候选记录和布尔矩阵是教学 fixture，不能当作实验结果。

## 1. 输入卡：动笔前必须确认

- 目标会议、年度、模板版本、单栏/双栏宽度、最小字号、文件格式；未确定时将尺寸标为暂定。
- 一句话说明这张图让读者理解什么；指出主角、辅助内容与读图顺序。
- 方法原文/算法/接口、符号定义、输入输出、训练与推理边界。
- 每条箭头的语义；哪些是数据、控制、梯度、反馈、检索或跨区引用。
- 每个数值或图形的来源；没有观测时使用明确标注的示意，不填预期性能。
- 交付用途及编辑器：模块拖拽用 draw.io，矢量细修用 SVG/Inkscape，精确公式和 LaTeX 原生结构用 TikZ，真实数据图用 Matplotlib/R。

输入缺少研究内容时只补画图必需的信息；版式、对齐和配色由助手处理。当前样板使用暂定 182 mm 双栏宽度，正文约 7.3–8 pt；不是特定会议的合规证明，不能直接缩成单栏。

## 2. 从方法到复杂图的步骤

1. **写设计契约**：核心信息、图原型、视觉层级、空间预算、可删内容与风险。样例见 design-contract.md。
2. **列语义图**：节点有稳定 ID 和输入输出，边写明 source/target、条件和线型。先核查科学关系，再决定排布。
3. **选总览与细节分工**：总览回答组件怎样共同工作；细节图说明核心判别/融合/更新机制。解释不清时拆图，避免把全部机制塞进一张。
4. **分配版面**：用面板、局部容器、主要模块与表格/矩阵形成层级。每个微图必须承担信息任务，不能把虚构曲线放进框中装饰。
5. **生成对象源文件**：保留原生整句文字、模块分组和独立连接线；图形不是一张底图。给全局返回路径预留专用通道。
6. **渲染与修复**：导出 PDF/PNG 后实际查看。在投稿宽度下检查文字、箭头、裁切、灰度可辨性与正文一致性。
7. **独立审校**：几何、科学语义、文字、审美四个视角；记录真实问题和修复，不能只凭自动评分。
8. **做一次真实编辑**：改文字、移动模块并重新导出；确认连接线和分组仍可用。仅生成 XML 不等于已验证 draw.io 的打开/导出。
9. **插入整页**：使用目标年度官方模板检查宽度、字重、图注、交叉引用及信息负担。当前提供的 A4 print-proof.pdf 仅供尺寸阅读，不代替官方版式验收。
10. **版本与交付**：保存生成源、编辑源、成图、图注、来源及审查记录。网站只展示已明确标注状态的版本。

## 3. 编辑与再生成的规则

- 在 https://app.diagrams.net/ 选择“打开现有绘图”，打开 `.drawio`；框内双击改字，拖动模块，拖拽连接线端点调整关系。嵌套模块可进入分组编辑；边连接到语义节点，而不是只贴一段固定线。
- 在 Inkscape 打开 `.svg`，文字是整句的原生文本。选择文字工具改字；框、表格格子、波形线和箭头为独立矢量对象。SVG 中的连接线不具备 draw.io 的自动跟随语义，移动后需要检查并重接。
- 代码生成路线：修改 `scripts/build_paper_grade_figures.py`，执行 `python scripts/build_paper_grade_figures.py` 后运行检查脚本。需要 Python 3、Pillow、PyMuPDF 和 PATH 中的 Inkscape；生成本身只依赖 Python 标准库和 Inkscape。
- 人工精修路线：将 `.drawio` 或 `.svg` 另存为 `-manual-vN`，把它登记为当前主档。后续成图从人工主档导出；**不要用生成器覆盖人工修改**。代码生成和人工主档是两条明确的版本路径，未配置双向自动同步。
- 不同渲染器的字距可能略有差异；SVG 与 draw.io 使用相同布局和标签，仍须检查人工编辑器中的实际效果。

## 4. 本轮实际遇到的问题与固定检查项

| 问题 | 为什么错 | 固定处理 |
|---|---|---|
| 只有 E2 卡片旁的一根输入箭头 | 误读成只有 E2 进入全部判别 | E1–E3 各接共享总线；查询条件单独进入 |
| 原始观测与核实后的更新都叫 verified feedback | 在验证前提前赋予证据有效性 | 原始观测用蓝虚线，核实后的更新用绿虚线；图例逐项定义 |
| 约束框写 review，却没有暂停分支 | 文本能力与图上控制路径不一致 | 单列人工审查/暂停节点；不走自动执行反馈 |
| unknown 被当成 pass 或数值零混用 | 条件未知与反证失败是不同事实 | 条件矩阵保留 YES/NO/?；本样板二值重用门控对 NO 和 ? 都不自动放行 |
| 文本宽度凭直觉估算 | 粗体和普通字体占用不同，长句越框 | 按实际字体测量，并实际检查成图；优先缩短标签、调整框尺寸 |
| 长反馈线穿过面板标题 | 图语义正确但读图受阻 | 回路走栏间或边缘通道，不让线穿文字 |
| 缩到单栏之后小字不可读 | 画布像素大不代表印刷字号足够 | 在物理宽度下验收；总览与细节分开使用 |
| 重绘覆盖人工稿 | 可编辑却不可维护 | 生成源与人工精修版本分别登记；当前主档只能有一个 |

## 5. 交付包与复用入口

每次完整交付至少包含：`design-contract.md`、生成脚本、`.drawio`、`.svg`、`.pdf`、`.png`、图注和来源说明、检查记录。本轮另外提供 182 mm 宽的 A4 阅读样张。所有元件均为本次独立绘制，无原论文图像素材。

使用模板时先删除样板中的科学内容再填真实方法；不要因为模板有门控、记忆或仿真模块，就认为新研究必须包含这些组件。只有已核实的真实实验才能进入结果图。

每轮复用：填写输入卡 → 复用组件和样式 → 改语义与拓扑 → 重建 → 四视角审校 → 真实编辑 → 记录新问题。新增经验先写“问题—原因—修复—验证”，达到可复用程度后再升为硬规则。
